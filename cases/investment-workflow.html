PERSONAL AI WORKFLOW · 个人场景实践

AI 投资研究与持仓监控

围绕个人投资研究，将行情与资讯获取、规则判断、报告交付和成交反馈连接起来，探索可持续运行的 AI 辅助流程。

个人自用多工具协同 / 状态反馈历史运行样例
01 / 业务问题

把分散的信息处理组织为固定的研究节奏

个人投资研究需要反复查看持仓、行情、资金、技术指标、公告与新闻。信息分散，连续场次之间也需要保持一致的持仓状态和判断口径。

目标

将资料获取、风险规则、候选排序与报告生成固定为可重复执行的流程。

人工边界

系统输出研究与决策辅助信息；交易确认和实际成交由本人完成，成交反馈用于更新下一场状态。

02 / 流程设计

从持仓输入，到成交反馈的闭环

  1. 触发与输入按 A 股交易日安排早盘与收盘前场次，读取持仓和风险规则。
  2. 资料与指标获取调用行情、资金、技术面与公告资讯工具；异常时使用备用数据源。
  3. 综合分析与规则判断结合持仓状态、风险限制和候选条件组织研究结论。
  4. 结构化报告生成 Markdown 报告，记录数据时间、优先事项、触发条件与风险。
  5. 人工决策本人阅读 PC / 微信报告并确认实际交易。
  6. 反馈与状态更新录入成交反馈，更新持仓状态，供下一场报告使用。

运行环境：Codex + Heartbeat；数据工具：东方财富妙想 mx-data、mx-search、mx-xuangu 及备用行情接口。历史设定场次为交易日 09:45 / 14:30。

03 / 关键决策

让每次输出能够回查、恢复和衔接

数据时间明确

报告记录生成时间、场次与数据时间，统一北京时间口径，降低调度偏差影响。

报告结构固定

包含市场概览、逐股研究结论、触发条件和 1–3 项优先事项，降低阅读与比较成本。

状态由成交反馈更新

以本人确认的实际成交衔接后续场次，减少持仓数量与成本信息漂移。

校验报告交付

处理超时、空数据、报告未生成及旧报告读取问题，结合重试、备用源与写入校验恢复。

06 / 恢复与验证边界

持续运行还需要验证交付与数据一致性

已处理的问题

UTC / 北京时间调度偏差、API 限频、请求超时、空数据，以及文件未覆盖和微信读取旧报告。

07 / 我的贡献与局限

用真实反馈改进长期运行流程

我的贡献

  • 定义使用场景、运行频次、风险规则、报告结构和人工反馈方式。
  • 与 Codex 共同迭代数据获取、备用源、重试、文件覆盖和状态同步逻辑。
  • 结合真实使用与成交反馈检查输出，记录异常并推动稳定性改进。

当前局限

  • 尚未证明长期收益、超额收益或建议准确率。
